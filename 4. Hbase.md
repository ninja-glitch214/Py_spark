# HBase – Command Shortnotes


One important distinction for your lab: HBase shell commands are not Linux terminal commands. First enter the shell using:

```
./Stop_all.sh
./start_hbase-container.sh
docker exec -it hbase-container hbase shell
```




A practical, revision-friendly HBase shell command reference covering table creation, CRUD operations, scanning, filtering, administration, and troubleshooting.

Since your lab environment uses Docker, enter the HBase shell with:

```
docker exec -it hbase-container hbase shell
```

All commands below are executed inside the HBase shell, unless marked as Linux/Docker commands.

## 1. Basic shell commands

|Command|Purpose|
|---|---|
|`help`|Display available commands.|
|`help 'create'`|Help for a specific command.|
|`version`|Display HBase version.|
|`status`|Display cluster status.|
|`whoami`|Display current user.|
|`exit`|Exit HBase shell.|
|`quit`|Exit HBase shell.|
|`clear`|Clear the terminal screen.|

## 2. Namespace commands

A namespace is a logical grouping of HBase tables.

```
list_namespace
```

List all namespaces.

```
create_namespace 'company'
```

Create a namespace.

```
describe_namespace 'company'
```

Display namespace details.

```
alter_namespace 'company', {METHOD => 'set', 'PROPERTY' => 'VALUE'}
```

Modify namespace properties.

```
drop_namespace 'company'
```

Delete an empty namespace.

```
list_namespace_tables 'company'
```

List tables inside a namespace.

Default namespace: `default`

System namespace: `hbase` (contains internal HBase tables).

For a table in a namespace:

```
create 'company:employees', 'personal', 'professional'
```

## 3. Table management commands

### Create a table

```
create 'employees', 'personal', 'professional'
```

Creates a table with two column families.

With options:

```
create 'employees',
  {NAME => 'personal', VERSIONS => 3},
  {NAME => 'professional', VERSIONS => 1}
```

- `VERSIONS` specifies how many cell versions to retain.
    
- Column families are defined when creating the table.
    

### List tables

```
list
```

List all tables.

```
list 'emp.*'
```

List tables matching a regular expression.

### Describe a table

```
describe 'employees'
```

Displays table properties and column-family details.

### Check table existence and status

```
exists 'employees'
is_enabled 'employees'
is_disabled 'employees'
```

### Enable and disable

```
disable 'employees'
enable 'employees'
```

Some administrative operations, such as dropping a table, require it to be disabled first.

### Drop a table

```
disable 'employees'
drop 'employees'
```

Destructive

Deletes the table and its data.

### Alter a table

Add a column family:

```
alter 'employees', NAME => 'address'
```

Change the maximum versions:

```
alter 'employees', NAME => 'personal', VERSIONS => 5
```

Delete a column family:

```
alter 'employees', NAME => 'address', METHOD => 'delete'
```

Check the changes:

```
describe 'employees'
```

Remember: HBase tables contain column families. Column qualifiers can be added dynamically when inserting data; they do not normally need to be declared individually.

## 4. Insert data – `put`

Syntax:

```
put 'table', 'rowkey', 'column_family:column_qualifier', 'value'
```

Example:

```
put 'employees', '101', 'personal:name', 'Alice'
put 'employees', '101', 'personal:age', '25'
put 'employees', '101', 'professional:department', 'IT'
put 'employees', '101', 'professional:salary', '60000'
```

Insert another row:

```
put 'employees', '102', 'personal:name', 'Bob'
put 'employees', '102', 'personal:age', '28'
put 'employees', '102', 'professional:department', 'HR'
```

Important:

- `101` is the row key.
    
- `personal` and `professional` are column families.
    
- `name`, `age`, `department`, and `salary` are column qualifiers.
    
- HBase stores values as bytes; it does not automatically enforce SQL-style data types.
    

## 5. Retrieve data – `get`

Get an entire row:

```
get 'employees', '101'
```

Get a specific column:

```
get 'employees', '101', 'personal:name'
```

Get multiple columns:

```
get 'employees', '101',
  {COLUMN => ['personal:name', 'professional:salary']}
```

Get multiple versions:

```
get 'employees', '101', {COLUMN => 'personal:name', VERSIONS => 3}
```

Get a particular timestamp version:

```
get 'employees', '101',
  {COLUMN => 'personal:name', TIMESTAMP => 1760000000000}
```

## 6. Retrieve multiple rows – `scan`

Display the entire table:

```
scan 'employees'
```

Display selected columns:

```
scan 'employees', {COLUMNS => ['personal:name', 'professional:salary']}
```

Limit the number of rows:

```
scan 'employees', {LIMIT => 5}
```

Scan from a starting row:

```
scan 'employees', {STARTROW => '101'}
```

Scan between row keys:

```
scan 'employees', {STARTROW => '101', STOPROW => '105'}
```

Important: `STARTROW` is inclusive and `STOPROW` is exclusive.

Display multiple versions:

```
scan 'employees', {VERSIONS => 3}
```

Display a particular column family:

```
scan 'employees', {COLUMNS => 'personal'}
```

Count rows:

```
count 'employees'
```

Count with progress intervals:

```
count 'employees', INTERVAL => 1000, CACHE => 1000
```

- `INTERVAL`: How frequently progress is reported.
    
- `CACHE`: Number of rows fetched per scanner batch.
    

## 7. Update and delete data

### Update a cell

Use `put` again with the same row key and column:

```
put 'employees', '101', 'personal:name', 'Alicia'
```

This creates a new cell version rather than performing an SQL-style in-place update.

### Delete a specific cell

```
delete 'employees', '101', 'personal:age'
```

### Delete a specific cell version

```
delete 'employees', '101', 'personal:name', 1760000000000
```

The timestamp identifies the version to delete.

### Delete an entire row

```
deleteall 'employees', '101'
```

### Delete a specific column family from a row

```
deleteall 'employees', '101', 'personal'
```

### Delete a specific column qualifier

```
deleteall 'employees', '101', 'personal:name'
```

### Truncate a table

```
truncate 'employees'
```

Destructive

Deletes all table data and recreates the table structure. Use it carefully; it is not the same as deleting a single row.

## 8. Filters – Conditional scanning

Filters allow you to retrieve only matching rows or cells instead of displaying the entire table.

### Row key filters

Match row keys with a prefix:

```
scan 'employees', {FILTER => "PrefixFilter('10')"}
```

Match an exact row key:

```
scan 'employees', {FILTER => "RowFilter(=, 'binary:101')"}
```

### Column value filters

Retrieve rows where a column has a particular value:

```
scan 'employees',
  {FILTER => "SingleColumnValueFilter('professional', 'department', =, 'binary:IT')"}
```

Filter based on a cell value:

```
scan 'employees', {FILTER => "ValueFilter(=, 'binary:Alice')"}
```

### Column filters

Match a column family:

```
scan 'employees', {FILTER => "FamilyFilter(=, 'binary:personal')"}
```

Match a column qualifier:

```
scan 'employees', {FILTER => "QualifierFilter(=, 'binary:name')"}
```

Match a qualifier prefix:

```
scan 'employees', {FILTER => "ColumnPrefixFilter('na')"}
```

### Combining filters

Use `FilterList` to combine conditions:

```
scan 'employees',
  {FILTER => "FilterList(AND, [PrefixFilter('10'), ValueFilter(=, 'binary:Alice')])"}
```

- `AND`: All conditions must match.
    
- `OR`: At least one condition must match.
    

### Important filter names

|Filter|Purpose|
|---|---|
|`PrefixFilter`|Matches row keys beginning with a prefix.|
|`RowFilter`|Filters based on row key comparison.|
|`ValueFilter`|Filters cells based on their values.|
|`SingleColumnValueFilter`|Filters rows based on a particular column's value.|
|`FamilyFilter`|Filters by column family.|
|`QualifierFilter`|Filters by column qualifier.|
|`ColumnPrefixFilter`|Matches column qualifiers with a prefix.|
|`ColumnCountGetFilter`|Limits the number of columns returned.|
|`KeyOnlyFilter`|Returns keys without the actual values.|
|`FirstKeyOnlyFilter`|Returns only the first cell of each row.|
|`FilterList`|Combines multiple filters.|

Exam trap: `SingleColumnValueFilter` evaluates a particular column to decide whether a row should be included. `ValueFilter` filters individual cells based on their values.

## 9. Increment and counters

HBase supports atomic increment operations.

Increment a counter by 1:

```
incr 'employees', '101', 'professional:visits'
```

Increment by 5:

```
incr 'employees', '101', 'professional:visits', 5
```

Retrieve the counter:

```
get_counter 'employees', '101', 'professional:visits'
```

Useful for:

- Page views.
    
- Visit counts.
    
- Event counters.
    
- Other incrementing numeric values.
    

`incr` is atomic, making it safer than reading a value, adding to it in application code, and writing it back.

## 10. Table maintenance commands

|Command|Purpose|
|---|---|
|`flush 'employees'`|Flushes the table's MemStore data to HFiles on disk.|
|`compact 'employees'`|Requests a minor compaction.|
|`major_compact 'employees'`|Requests a major compaction.|
|`status`|Shows cluster status.|
|`balancer`|Runs the region balancer.|
|`balancer_switch true`|Enables the balancer.|
|`balancer_switch false`|Disables the balancer.|

Compaction:

- Minor compaction merges selected smaller HFiles.
    
- Major compaction merges HFiles in a region and can remove deleted or expired data that is eligible for cleanup.
    

## 11. Snapshots and backup-related commands

A snapshot captures a table's state without making a full independent copy of all its underlying HFiles.

Create a snapshot:

```
snapshot 'employees', 'employees_backup'
```

List snapshots:

```
list_snapshots
```

Clone a snapshot into a new table:

```
clone_snapshot 'employees_backup', 'employees_copy'
```

Restore a table from a snapshot:

```
disable 'employees'
restore_snapshot 'employees_backup'
enable 'employees'
```

Delete a snapshot:

```
delete_snapshot 'employees_backup'
```

Difference:

- `clone_snapshot`: Creates a new table from a snapshot.
    
- `restore_snapshot`: Restores an existing table to the snapshot state.
    

## 12. Column family properties – Important options

These properties are specified while creating or altering a column family.

|Property|Purpose|
|---|---|
|`VERSIONS`|Maximum number of cell versions to retain.|
|`TTL`|Time-to-live in seconds.|
|`BLOCKCACHE`|Enables/disables block cache.|
|`COMPRESSION`|Sets compression algorithm.|
|`IN_MEMORY`|Indicates preference for keeping data in block cache.|
|`BLOOMFILTER`|Configures Bloom filter type.|
|`MIN_VERSIONS`|Minimum versions to retain, subject to TTL and other rules.|

Example:

```
create 'students',
  {NAME => 'personal', VERSIONS => 3, TTL => 86400},
  {NAME => 'academic', VERSIONS => 5}
```

This creates:

- `personal`: retains up to 3 versions, with a TTL of 86400 seconds (1 day).
    
- `academic`: retains up to 5 versions.
    

Change properties later:

```
alter 'students', NAME => 'personal', TTL => 172800
```

## 13. Important scan options

These options are particularly useful in lab tasks.

|Option|Purpose|
|---|---|
|`COLUMNS`|Select column families or qualifiers.|
|`STARTROW`|Starting row key, inclusive.|
|`STOPROW`|Ending row key, exclusive.|
|`LIMIT`|Maximum number of rows to return.|
|`VERSIONS`|Number of cell versions to retrieve.|
|`TIMESTAMP`|Retrieve data at a specific timestamp.|
|`TIMERANGE`|Restrict results to a timestamp range.|
|`FILTER`|Apply a filter condition.|
|`REVERSED`|Scan in reverse row-key order.|
|`CACHE`|Set scanner caching size.|

Example combining options:

```
scan 'employees', {
  COLUMNS => ['personal:name', 'professional:salary'],
  STARTROW => '101',
  STOPROW => '110',
  LIMIT => 5
}
```

Create and populate a table

```

```

